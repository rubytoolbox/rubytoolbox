# Deployment

**This document describes how the production app is deployed and operated on [fly.io](https://fly.io/), where hosting is provided through a [gem.coop](https://gem.coop) sponsorship agreement.**

See [Configuration](./configuration.md) for the environment variables the app expects.

## Container image

Production runs the [Dockerfile](../Dockerfile) at the repository root: a multi-stage
image whose toolchain (ruby as a precompiled binary, node & pnpm for the asset build)
is provided by [mise](https://mise.jdx.dev) from the same pinned version files used
for local development and CI. The runtime stage runs as the non-privileged
`rubytoolbox` user with jemalloc preloaded and YJIT enabled.

## Processes

Two process groups, mirroring the former Procfile:

* `web` — puma app server (listening on port 5000 by default)
* `worker` — sidekiq for background jobs, including the recurring job scheduler

## Migrations & release tasks

The deployment runs `bundle exec rake db:migrate release` as the fly.io
[release command](https://fly.io/docs/reference/configuration/#run-one-off-commands-before-releasing-a-deployment)
before new machines go live — the direct equivalent of the former Heroku release
phase. The `release` task (see [lib/tasks/release.rake](../lib/tasks/release.rake))
queues post-deployment work such as refreshing the public database export.

## Recurring jobs

Recurring work is scheduled by [sidekiq-scheduler](https://github.com/sidekiq-scheduler/sidekiq-scheduler),
configured in [config/sidekiq.yml](../config/sidekiq.yml): an hourly `CronJob`
invokes the [Cron service](../app/services/cron.rb), which dispatches jobs based
on the current time (daily catalog syncs, the 4-hourly selective database export,
hourly update scheduling). The scheduler runs inside the `worker` process — no
external cron infrastructure is required.

## Production rails console

With [flyctl](https://fly.io/docs/flyctl/) installed and authenticated:

```
mise run console:fly
```

This wraps `fly ssh console --pty -C "bin/rails console"`. (The image keeps the
mise-managed ruby toolchain on `PATH`, so any other one-off command works the
same way, e.g. `fly ssh console -C "bin/rails db:migrate:status"`.)

## Database exports

The [selective database export](../app/models/database/selective_export.rb) for
local development setups is generated by a recurring job (and after each
deployment via the release task), stored on S3 through Active Storage, and served
at [/database/exports/selective](https://www.ruby-toolbox.com/database/exports/selective) —
this is platform-independent and requires only the `S3_*` environment variables.
